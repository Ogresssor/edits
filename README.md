# Edits Studio v2

Локальная монтажная система: анализ → план → предпросмотр → финал → проверка → согласование → план публикаций. Основной рендер — FFmpeg без обязательного After Effects. Обработка не публикует видео.

Старый код сохранён в [archive/legacy-2026-11-15](https://github.com/Ogresssor/edits/tree/archive/legacy-2026-11-15), коммит `f2c76f7f62a733ab0788c17b852a0bbc66fcaf6a`.

## Запуск

Python 3.11+, FFmpeg с libx264 и libass. Python-зависимостей у ядра нет. Установите FFmpeg в PATH или задайте `EDITS_FFMPEG` полным путём к исполняемому файлу. В текущей установке также поддерживается имеющийся бинарник imageio-ffmpeg.

```powershell
python edits.py doctor
python edits.py ingest "D:\Movies\movie.mkv"
python edits.py analyze "D:\Movies\movie.mkv"
python edits.py render examples/story.json --preview --profile clean
python edits.py render examples/story.json --profile clean
python edits.py check ".local\renders\story-01\REVISION\video.mp4"
python edits.py approve SHA256 --reviewer Mikhail --reviewed-video-and-audio
python edits.py queue SHA256 --at "2026-12-01T09:00:00+03:00"
python edits.py status
```

Шаблон story.json необходимо заполнить реальным исходником, картой сцен и проверенными репликами. Согласование привязано к SHA-256. `queue` создаёт **локальный план**, ничего не загружает в YouTube.

## Реализовано

- Регистрация исходника; полный хэш кэшируется по пути/размеру/mtime/ctime и пересчитывается при изменении. Для защиты от преднамеренной подмены с сохранёнными атрибутами требуется повторный полный хэш.
- Техническая карта смен планов всего исходника. Пропуски в покрытии блокируют монтаж. Она не заменяет расшифровку и смысловой разбор.
- Один JSON-план: завязка, развитие, развязка, контекст, причина отбора, оценка, интервалы, дорожка, субтитры, лицензия музыки.
- Предпросмотр 540×960 и финал 1080×1920. Один проход кодирования, без промежуточных MOV и запуска AE. Никаких случайных вставок и speed ramp.
- Подложка с приглушением на речи и нормализацией. Полный исходный кадр сохраняется: clean/accent используют размытый фон, cinema — спокойные поля.
- Отдельная папка по хэшу входов. Финальный файл появляется после успешного процесса и проверки длительности. Неизменный экспорт используется повторно.
- Полное декодирование, чёрные кадры/зависания, длительность, громкость и true peak. Это технический контроль, не гарантия идеального монтажа или отсутствия Content ID.
- Подмена одобренного файла блокирует постановку в очередь. Две версии одинаковых исходных интервалов не ставятся повторно даже после переименования сюжета. Семантические дубли со слегка изменёнными интервалами требуют ручного контроля.
- SQLite с транзакциями, уникальными сюжетами и слотами. Нет скрытых догрузок и переносов.

## Границы версии

Это проверенное ядро, а не законченная автономная фабрика. Автоматические ASR, смысловой отбор сцен, кадрирование по лицам, интерфейс редактора, аналитика YouTube и загрузчик v2 **ещё не подключены**. История и субтитры заполняются вручную. Следующий шаг — одна сцена с тремя оформлениями и полный разбор фильма перед партией.

Видео длиннее 60 секунд отмечаются предупреждением; отсутствие блокировки локально не устанавливается. Серверная очередь YouTube при перестройке не менялась.

## Проверки

```powershell
python -m unittest discover -s tests -v
python tests/smoke_render.py
```

Вторая команда создаёт синтетическое видео и музыку, строит карту, экспортирует финал и три предпросмотра, проверяет декодирование/звук/кэш. Это не проверка реального фильма. Результат — `.local/smoke/result.json`.
