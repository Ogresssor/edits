# Архитектура Go

`cmd/edits` — CLI и ограниченный пул batch-воркеров. `internal/studio/model.go` — типизированные планы и валидация. `media.go` — FFmpeg, таймауты, отмена и карта всего исходника. `design.go` — встроенные шрифты, ASS, анимация текста и явные акценты сцены. `render.go` — ревизии, рендер и независимая QA. `store.go` — согласования и локальный план. `demo.go` — полностью локальные демонстрации.

## Хранение

Внешних Go-зависимостей и CGO нет. Для небольшого локального реестра выбран JSON state.json с записью во временный файл, fsync и переименованием. Общая блокировка через эксклюзивное создание файла защищает изменения состояния между процессами. При конфликте процесс завершается с понятной ошибкой; не перетирает чужое состояние. Повреждённый реестр не сбрасывается молча. Для серверного многопользовательского режима понадобится отдельное транзакционное хранилище; текущая версия его не изображает.

Старая SQLite не переиспользуется и не запускает прежнюю очередь. Корень по умолчанию `.local/go`. Ключ сюжета — хэш исходника и точных исходных интервалов. Согласование — SHA-256 экспортированного файла. После отрицательной QA согласование отзывается, запись в плане получает blocked_qa.

## Производство

Исходник → полная техническая карта → редакторский разбор и кандидаты → план → локальный черновик → финал → QA → непрерывный просмотр/прослушивание → согласование → локальный план. Полная карта склеек не является просмотром фильма или расшифровкой. Не выбирать несколько участков и не объявлять это полным разбором.

Рендер одного задания блокируется по хэшу плана, профиля и качества. Блокировка с PID остаётся после аварийного завершения; перед её удалением проверить, что процесс завершён. Ревизии не перезаписывают одобренные файлы. Чужие квитанции и старый формат receipt не принимаются. Большая часть работы идёт в одном процессе FFmpeg, Go управляет заданиями и результатами.

`batch --jobs 1..4` даёт ограниченную параллельность; больше воркеров не гарантирует более быстрый рендер, если CPU/GPU/диск уже загружены. Основной кодек — CPU libx264. GPU-кодеры и бенчмарк фильма ещё не внедрены.

## Внешние действия

Ни один текущий путь Go-приложения не импортирует OAuth и не публикует видео. Будущий загрузчик обязан проверять разрешение на конкретный экспорт, канал и живое расписание; сразу сохранять полученный ID, отдельно подтверждать серверный статус и останавливаться при неопределённом результате POST. Пользователь отложил этот этап до завершения локальных тестов.

Распознавание речи можно вынести в отдельный нативный процесс (например, whisper.cpp), но оно ещё не подключено. Python не используется как скрытый обязательный воркер.
