# Архитектура

`core.py` — планы, хэши, реестр экспортов, согласования, локальная очередь. `analysis.py` — карта всего исходника с явным методом проверки. `media.py` — шлюз к FFmpeg с таймаутами и аргументами без shell. `render.py` — оформление, ASS, монтаж, звук, экспорт, QA. `cli.py` — явные команды. Обработка не импортирует Google OAuth и загрузчик. Медиа и SQLite — в `.local`, исходники могут лежать на отдельном диске.

## Процесс

1. Зарегистрировать исходник; выбрать и прослушать дорожку.
2. Просканировать весь фильм. Дополнить техническую карту расшифровкой и редакторским разбором всех участков. Поиск склеек не является смысловым анализом.
3. Разделить кандидатов на сильные/средние/слабые: причина, завязка, развитие, развязка. Без квоты «три ролика из фильма».
4. Собрать локальный черновик. Проверить смысл, стыки фраз, реакции, читаемость, музыку и безопасные зоны интерфейса Shorts.
5. Финал и техническая проверка. Непрерывно просмотреть и прослушать финальный MP4.
6. Согласовать конкретный SHA, затем планировать публикацию.
7. Будущий отдельный загрузчик сверяет канал, живую очередь и дубли перед записью. ID сохраняется сразу после ответа сервера. Прерванный POST без ID — остановка для сверки, не повторная вставка.

## Скорость

Карта и хэш исходника кэшируются. Рендер читает выбранные интервалы с предварительным seek, сводит и кодирует одной командой. Предпросмотр вдвое меньше по сторонам. Неизменный план использует готовый артефакт.

Пока используется CPU libx264. NVENC/QSV, бюджеты VRAM, воркеры и бенчмарк реального фильма — следующий этап. Синтетический тест не доказывает скорость на фильме. Одновременно рендерить одну ревизию пока нельзя: блокировки задач ещё не добавлены.

## Следующие модули

- ASR: один проход по выбранной дорожке, слова/тайминги в кэше, словарь имён, ручная вычитка.
- Кадрирование: отдельно по исходным планам, контроль лиц/предметов/жестов; без прыжков окна внутри плана.
- QA речи: границы фраз, сопоставление субтитров; флаг ASR не признаётся дефектом автоматически.
- Публикация: изолированный процесс, `planned → uploading → uploaded → server_verified`, без повторов при неопределённом результате.
- Аналитика: снимки через 24/48/72 часа; показы в ленте, продолжили смотреть, средний процент, удержание, ограничения. Эти данные нельзя вывести из общего числа просмотров.
